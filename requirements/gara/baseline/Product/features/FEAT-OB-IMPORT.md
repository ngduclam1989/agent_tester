# FEAT-OB-IMPORT: Import tồn đầu kỳ

## 1. User Story

**As** chủ garage / kế toán, **I want** import số lượng và giá trị tồn theo mã sản phẩm nội bộ từ file mẫu với bước kiểm tra dữ liệu, **so that** tôi thiết lập nhanh tồn khởi đầu và tránh ghi dữ liệu lỗi.

## 2. Acceptance Criteria

### Nhóm A — Tải file

- [ ] **AC-1**: Mở màn import

  - Tại: danh sách tồn đầu kỳ, nút **"Import tồn đầu kỳ"**.
  - Khi: chủ garage nhấn nút.
  - Thì: hệ thống mở màn **"Tải lên danh sách tồn đầu kỳ"** — **single page** (không wizard stepper), gồm section **"Thông tin cơ bản"** (link tải template + vùng chọn file). Header trái: **← back arrow** (quay về danh sách). Header phải: 2 nút **"Huỷ bỏ"** + **"Xác nhận"** (nút **"Xác nhận"** chỉ enable khi có file hợp lệ đã parse xong). Preview hiển thị **inline bên dưới** vùng chọn file sau khi file được phân tích (AC-4). **Không có bước riêng** — mọi thao tác trong cùng 1 màn.
- [ ] **AC-2**: Link tải template mẫu

  - Tại: section **"Thông tin cơ bản"**, link **"📄 Mẫu file danh sách tồn đầu kỳ.xlsx"**.
  - Khi: chủ garage nhấn link.
  - Thì: hệ thống tải file template `.xlsx` gồm **2 tab**:
    - **Tab "Danh sách tồn sản phẩm"** (tab nhập liệu chính) — cột: **STT, Mã nội bộ \*, Tên sản phẩm \*, ĐVT \*, Kho \*, Số lượng tồn \*, Giá trị tồn, Tồn đến ngày \***. Dòng hướng dẫn (dòng 2) ghi hint: "Nhập tên ĐVT", "Nhập tên kho".
    - **Tab "ĐVT"** (tham chiếu) — cột: STT, Mã, Tên ĐVT. Liệt kê danh mục đơn vị tính master để user tra cứu tên ĐVT hợp lệ.
  - Lưu ý: cột **ĐVT** nhập theo **tên ĐVT** (không nhập mã — BR-OB-010 validate khớp ĐVT chính của mã sản phẩm). Cột **Kho** nhập theo **tên kho** (BR-OB-005). Cột **STT** là số thứ tự (không bắt buộc).
- [ ] **AC-3**: Chọn file import

  - Tại: vùng kéo thả file (drop zone với text **"Kéo thả hoặc nhấn để chọn tệp"**, hint hỗ trợ `.xlsx`).
  - Khi: chủ garage kéo thả hoặc nhấn chọn file.
  - Thì: hệ thống nhận file (cho phép nhiều kho trong cùng file theo cột kho), hiển thị **card file** (tên + dung lượng + icon thùng rác để xóa) ngay dưới drop zone, và **render preview inline** bên dưới (AC-4). Không ghi dữ liệu ở bước này.
- [ ] **AC-3b**: Kiểm tra cấp file (trước khi preview từng dòng)

  - Tại: chọn file.
  - Khi: file **không phải `.xlsx`** hoặc **không đọc được**.
  - Thì: hệ thống báo lỗi định dạng, **không chuyển** sang bước kiểm tra dữ liệu.
  - Khi: file hợp lệ nhưng **không có dòng dữ liệu nào** (file rỗng).
  - Thì: hệ thống báo **"File không có dữ liệu"**, không cho xác nhận import.
  - Khi: file có **> 500 dòng dữ liệu**.
  - Thì: hệ thống **từ chối toàn bộ lần import ngay ở bước kiểm tra** (không ghi dòng nào), báo mã lỗi **`ERR-INV-048`** ("Vượt giới hạn 500 dòng/lần import tồn đầu kỳ — vui lòng tách file"). Áp dụng ở cả tầng kiểm tra lẫn ghi (**BR-OB-004b**).

### Nhóm B — Preview / Kiểm tra dữ liệu (inline dưới drop zone)

- [ ] **AC-4**: Hiển thị tổng quan

  - Tại: vùng preview (hiển thị inline dưới drop zone sau khi file được phân tích).
  - Khi: file được phân tích.
  - Thì: hệ thống hiển thị **3 thẻ**: **Tổng cộng**, **Hợp lệ**, **Lỗi**; ô tìm placeholder **"Tìm theo mã nội bộ, tên sản phẩm"**; 3 filter tab trạng thái **"Tất cả / Hợp lệ / Lỗi"**; nút **"Tải file lỗi"** (xuất `.xlsx` chỉ các dòng "Lỗi" kèm cột Lý do lỗi) — chỉ enable khi Lỗi > 0. Bảng preview với cột **"STT"**, **"Dòng"**, **"Tồn đến ngày"**, **"Kho"**, **"Mã nội bộ"**, **"Tên nội bộ"**, **"ĐVT"**, **"SL tồn"**, **"Giá trị tồn"**, **"Trạng thái"**, **"Lý do lỗi"** + dòng **Tổng** (tổng SL tồn + Giá trị tồn); phân trang.
- [ ] **AC-5**: Trạng thái dòng + đánh dấu lỗi

  - Tại: bảng preview, cột **"Trạng thái"** hiển thị 1 trong 2 badge — **"Hợp lệ"** (nền xanh, text đậm) hoặc **"Lỗi"** (nền đỏ, text đậm); cột **"Lý do lỗi"** (chỉ hiện text khi Trạng thái = "Lỗi"; dòng "Hợp lệ" để trống) — wording rút gọn theo Figma (vd **"Sai mã"**, **"Kỳ đã đóng"**, **"ĐVT lệch"**...).
  - Khi: dòng vi phạm validate.
  - Thì: hệ thống set Trạng thái = **"Lỗi"** + hiển thị lý do rút gọn (UI) + gắn **mã lỗi** API đầy đủ (contract):
    - **"Mã sản phẩm nội bộ không tồn tại"** — `ERR-INV-009`.
    - Mã sản phẩm **ngừng hoạt động** — `ERR-INV-010`.
    - **Số lượng tồn ≤ 0** — `ERR-INV-032`.
    - **Giá trị tồn < 0** (cho phép = 0 hoặc để trống) — `ERR-INV-033`.
    - **ĐVT trong file khác ĐVT chính** của mã sản phẩm (kể cả ĐVT quy đổi cũng báo lỗi) — `ERR-INV-019`.
    - Thiếu trường bắt buộc — `ERR-INV-017` / sai định dạng ngày — `ERR-INV-018`.
    - **Kho không tồn tại** trong danh mục kho của garage — `ERR-INV-020`.
    - **"Tồn đến ngày" rơi vào kỳ kế toán đã đóng** — `ERR-INV-024`.
    - **Chèn OB làm tồn (mã + kho) < 0 tại bất kỳ thời điểm nào từ "Tồn đến ngày" trở đi** (check point-in-time, đối xứng với xóa) — `ERR-INV-036`.
    - **"Tồn đến ngày" sau/cùng ngày phát sinh phiếu nhập/xuất đã ghi sổ** của (mã + kho) — OB phải là điểm khởi đầu, **trước mọi phiếu** — `ERR-INV-035`.
  - Khi: dòng có **cùng mã + cùng kho** với OB đã import trước đó **HOẶC** với dòng khác trong **cùng file**.
  - Thì: hệ thống **CHẶN** — `ERR-INV-034`: mỗi (mã + kho) chỉ có **một** OB; dòng trùng **không được ghi** (BR-OB-012). (Muốn đổi OB → xóa OB cũ rồi import lại.)
- [ ] **AC-6**: Xác nhận import (all-or-nothing)

  - Tại: header trên phải, nút **"Xác nhận"**.
  - Khi: **toàn bộ dòng trong file đều hợp lệ** (không có dòng nào ở trạng thái "Lỗi") và chủ garage xác nhận.
  - Thì: hệ thống ghi **toàn bộ dòng** trong file vào **bảng tồn đầu kỳ** (`opening_balance_line` — bảng dữ liệu mới thuộc `gf-inventory`) trong **1 transaction all-or-nothing**. Mỗi dòng OB ghi đủ 3 nhóm field:
    - **(a) Nghiệp vụ (từ file)** — `product_internal_code` (Mã sản phẩm nội bộ, resolve → productInternalId), `warehouse_id` (Kho, resolve từ tên kho), `uom_id` (ĐVT chính của mã sản 3phẩm — server enforce khớp, không lấy từ file), `stock_quantity` (SL tồn > 0), `stock_value` (Giá trị tồn ≥ 0), `as_of_date` (Tồn đến ngày).
    - **(b) Tenant + audit (server derive)** — `tenant_id` / `origin_tenant_id` (từ `TenantContext` — Critical Rule #10), `imported_by` (userId từ auth context), `imported_at` (server timestamp), `source_filename` + `source_checksum` (SHA-256 nội dung file — BR-OB-CMN-001).
    - **(c) System key** — `id` (UUID), `created_at` / `updated_at` (audit chuẩn).
  - Sau khi commit bảng OB thành công → hệ thống **trigger engine sổ tồn chung** (**BR-STKV2-001** — Import OB là tình huống #1 trong 5 tình huống cập nhật sổ tồn) → cascade tính lại tồn cuối ngày của (mã+kho+gara) từ "Tồn đến ngày" trở đi. Rollback bảng OB nếu cascade fail (giữ atomicity BR-OB-004a).
  - Khi: file có **bất kỳ dòng lỗi nào** (kể cả 1 dòng — gồm cả dòng trùng (mã+kho) theo BR-OB-012).
  - Thì: hệ thống **chặn toàn bộ lần import — không ghi dòng nào vào bảng OB**, nút **"Xác nhận"** **disabled**, kèm cảnh báo **"Còn dòng lỗi — vui lòng sửa file rồi kiểm tra lại trước khi import."** (BR-OB-004a).
- [ ] **AC-7**: Huỷ bỏ

  - Tại: header trên phải, nút **"Huỷ bỏ"** (hoặc ← back arrow trên trái).
  - Khi: chủ garage nhấn.
  - Thì: hệ thống đóng màn import, quay về danh sách tồn đầu kỳ (`FEAT-OB-LIST`) — không ghi dữ liệu.

### Nhóm C — Kết quả import

  - Tại: sau khi ghi transaction thành công (AC-6).

  - Thì: hệ thống hiển thị **toast thành công** ở góc phải trên với wording **"Tải tệp lên thành công!"** (theo Figma) + điều hướng về màn `FEAT-OB-LIST`. **KHÔNG hiển thị màn kết quả riêng** — vì bước preview (AC-4/AC-5) đã cho user thấy số dòng hợp lệ / lỗi + tải file lỗi trước khi confirm; audit (Người import / Ngày import / Filename / Checksum) lưu backend, tra được qua danh sách (cột Người import + Ngày import).

## 5. Business Rules

- **BR-OB-001 / 002 / 003**: Cấu trúc dòng; không gắn kỳ thủ công (liên hệ qua "Tồn đến ngày"); chỉ SL + giá trị.
- **BR-OB-004**: Chỉ thêm mới, bắt buộc qua bước kiểm tra, `.xlsx`, nhiều kho/file.
- **BR-OB-004a**: **All-or-nothing** — chỉ ghi khi toàn bộ dòng trong file hợp lệ; có bất kỳ dòng lỗi nào → chặn cả file, không ghi dòng nào (bảo toàn tính chính xác số dư mở đầu).
- **BR-OB-004b**: **Giới hạn 500 dòng/lần** + validate cấp file (định dạng `.xlsx`, file rỗng, vượt 500 dòng → `ERR-INV-048`).
- **BR-OB-005**: Kho từ danh mục garage; kho không tồn tại → `ERR-INV-020`.
- **BR-OB-006 .. 011**: Validate (mã không tồn tại / ngừng hoạt động, SL ≤ 0, giá trị < 0, ĐVT lệch, thiếu trường / sai ngày).
- **BR-OB-012**: OB **duy nhất theo (mã+kho)** — trùng (mã+kho, gồm trong cùng file) → **CHẶN**, không ghi.
- **BR-OB-013**: Chặn import dòng có "Tồn đến ngày" thuộc kỳ đã đóng; ngày không thuộc kỳ nào → cho import.
- **BR-OB-015**: Chặn import nếu chèn OB làm tồn âm point-in-time.
- **BR-OB-016**: Chặn import nếu "Tồn đến ngày" sau/cùng ngày phiếu phát sinh của (mã+kho) — OB phải trước mọi phiếu (`ERR-INV-035`). Import OB hợp lệ → **tính lại (cascade) tồn-đến-ngày** các mốc sau.
- **Cascade sổ tồn** (gắn AC-6): import OB hợp lệ → tính lại tồn cuối ngày của (mã+kho+gara) từ "Tồn đến ngày" trở đi (**BR-STKV2-001** — Import OB là tình huống #1 trong 5 tình huống cập nhật sổ tồn; engine tính lại từ (bảng OB + phiếu detail)).
- **BR-OB-CMN-001**: Audit người import / thời gian / file + checksum.
- **BR-OB-CMN-002**: Phân quyền — chủ garage + kế toán quyền ngang nhau (AC-9).

## 6. Edge Cases

- **EC-1**: File có dòng hợp lệ + lỗi (dù chỉ 1 dòng lỗi) → **chặn toàn bộ, không ghi dòng nào** (all-or-nothing — BR-OB-004a). User phải sửa file rồi kiểm tra lại.
- **EC-2**: Toàn bộ dòng lỗi → không ghi dòng nào.
- **EC-3**: Một file chứa nhiều kho → ghi đúng từng kho theo cột kho.
- **EC-4**: Dòng có ngày thuộc kỳ đã đóng → đánh dấu lỗi/chặn, không ghi.
- **EC-5**: Dòng có Kho không tồn tại trong danh mục → lỗi `ERR-INV-020`, không ghi.
- **EC-6**: Chèn OB làm tồn (mã+kho) âm về sau → lỗi `ERR-INV-036`, không ghi.
- **EC-7**: Ngày "Tồn đến ngày" không thuộc kỳ nào (garage chưa lập kỳ) → vẫn cho import.
- **EC-8**: 2+ dòng trùng (mã+kho) (cùng file hoặc với OB đã có) → **chặn** dòng trùng, không ghi (`ERR-INV-034`).
- **EC-9**: "Tồn đến ngày" sau/cùng ngày một phiếu nhập/xuất đã có của (mã+kho) → lỗi `ERR-INV-035`, không ghi.
- **EC-10**: Import OB hợp lệ với "Tồn đến ngày" **trước** phiếu đã có → hệ thống **tính lại tồn-đến-ngày** (cascade forward) các mốc sau để phản ánh OB.
- **EC-11**: "Tồn đến ngày" ở **tương lai** (> ngày hiện tại) → **cho phép import**, không chặn.
