# FEAT-OB-LIST: Danh sách tồn đầu kỳ

---

| Priority    | P1                               |
| Status      | PLANNED                          |

## 1. User Story

**As** chủ garage / kế toán, **I want** xem danh sách các dòng tồn đầu kỳ với tìm kiếm, bộ lọc và tổng hợp, **so that** tôi rà soát số lượng / giá trị tồn khởi đầu và chọn dòng để xóa khi cần.

## 2. Acceptance Criteria

### Nhóm A — Hiển thị danh sách

- [ ] **AC-1 [web]**: Mở màn danh sách (Web GMS)

  - Tại: chức năng **"Tồn đầu kỳ"**.
  - Khi: chủ garage truy cập.
  - Thì: hệ thống hiển thị màn **"Tồn đầu kỳ / Danh sách tồn đầu kỳ"** (màn mặc định) với mô tả **"Màn mặc định khi bấm Tồn đầu kỳ; hỗ trợ lọc, rà soát và xóa nhiều dòng theo guardrail."**, ô tìm kiếm + 3 bộ lọc, bảng danh sách có checkbox chọn dòng, dòng Tổng, phân trang, và nút **"Import tồn đầu kỳ"** (luôn hiển thị, top-right). Nút **"Xoá các dòng đã chọn"** **chỉ hiển thị khi có ≥1 dòng được tick** (vị trí bên trái ô tìm kiếm) — ẩn ở trạng thái mặc định.
- [ ] **AC-1b [mobile]**: Mở màn danh sách (App Garage — view-only)

  - Tại: mission tile **"Quản lý kho hàng"** → tile **"Tồn đầu kỳ"** trên màn Home (Sảnh chính).
  - Khi: chủ garage / kế toán tap tile.
  - Thì: hệ thống push route mở màn **"Tồn đầu kỳ"** mobile (verbatim Figma node `21290:52697`) — AppBar: `← back` + title **"Tồn đầu kỳ"** + icon **🔍 search** + icon **⚙ filter**; body: SliverList of card view-only; footer sticky **"Tổng"** (aggregate). **KHÔNG hiển thị**: checkbox chọn dòng / nút "Import tồn đầu kỳ" / nút "Xoá các dòng đã chọn" (view-only per UX-FLOW §1). Back về Home + preserve back stack.
- [ ] **AC-2 [web]**: Cột hiển thị trong bảng (Web GMS)

  - Tại: bảng danh sách.
  - Khi: bảng được render.
  - Thì: hệ thống hiển thị: checkbox chọn, **"STT"**, **"Tồn đến ngày"**, **"Kho"**, **"Mã nội bộ"**, **"Tên nội bộ"**, **"ĐVT"**, **"Số lượng tồn"**, **"Giá trị tồn"**, **"Người import"**, **"Ngày import"**, **"Thao tác"** (icon sửa ✏️ + icon xóa 🗑️ per dòng). Sắp xếp mặc định: **Ngày import mới nhất lên đầu**.
- [ ] **AC-2b [mobile]**: Card layout (App Garage)

  - Tại: danh sách mobile (Figma node `21290:52697`).
  - Khi: card được render.
  - Thì: mỗi card hiển thị: **header** = `#{productCode}` (blue bold, VD `#IP-BP-0001`) + **item name** = `{productName}` (bold, VD "Lọc dầu động cơ Toyota") + **separator** + **5 field rows**: (1) 🏢 `Kho: {warehouseName}`; (2) 📅 `Tồn đến ngày: {asOfDate}` (format `dd/MM/yyyy`); (3) 🛒 `Số lượng: {quantityOnHand}`; (4) 💰 `Giá trị tồn: {valueOnHand}` (VN thousand separator, VD `1.760.000`); (5) 📦 `ĐVT: {mainUnitName}` (map SDL `OpeningBalanceLine.mainUnitName` BFF-enriched per agg-garage-graph-graphql v7.50 §3g.1; fallback `mainUnitCode` khi enrichment nullable miss). **KHÔNG hiển thị**: STT / Người import / Ngày import / checkbox / cột Thao tác. Sắp xếp mặc định: **Ngày import (createdAt) mới nhất lên đầu** (giống web).
- [ ] **AC-3 [cross-platform]**: Dòng tổng

  - Khi: bảng / list được render.
  - Thì: hệ thống hiển thị **"Tổng"** = tổng **Số lượng tồn** + tổng **Giá trị tồn** của các dòng đang hiển thị theo bộ lọc. Nguồn dữ liệu: `PagedOpeningBalanceData.aggregates` (`totalQuantity` + `totalValue`) — server-side tính, không phải sum của trang hiện tại.
- [ ] **AC-3b [web]**: Trạng thái trống (chưa có OB nào cho garage) — Web GMS

  - Tại: màn danh sách tồn đầu kỳ.
  - Khi: garage hiện tại **chưa import dòng OB nào** (bảng `opening_balance_line` không có record thuộc tenant).
  - Thì: hệ thống hiển thị:
    - Header giữ đầy đủ: page title **"Danh sách tồn đầu kỳ"** + ô tìm kiếm + 3 bộ lọc (Kho / Người import / Ngày import) + nút **"Import tồn đầu kỳ"** (top-right, luôn enable).
    - Vùng bảng: **icon minh hoạ empty** + text **"Không có dữ liệu"** ở giữa (không hiển thị header cột hoặc chỉ hiển thị header cột không có row).
    - **KHÔNG hiển thị**: dòng "Tổng", phân trang, nút **"Xoá các dòng đã chọn"** (vì không có dòng để tick).
  - Khi: chủ garage nhấn **"Import tồn đầu kỳ"** ở trạng thái trống.
  - Thì: mở wizard import (`FEAT-OB-IMPORT`) — luồng khởi tạo dữ liệu OB lần đầu cho garage.
- [ ] **AC-3b-mobile [mobile]**: Trạng thái trống — App Garage

  - Tại: màn "Tồn đầu kỳ" mobile.
  - Khi: garage hiện tại chưa có dòng OB nào (server trả `PagedOpeningBalanceData.totalElements = 0`).
  - Thì: hệ thống hiển thị: AppBar giữ đầy đủ (title + 🔍 search + ⚙ filter đều enable — user vẫn có thể apply search/filter); vùng body: card empty giữa màn với text **"Chưa có tồn đầu kỳ"**. **KHÔNG có CTA** (view-only per UX-FLOW §1 — mobile không có nút "Import tồn đầu kỳ"). **KHÔNG hiển thị**: footer "Tổng" + loading indicator.

### Nhóm B — Tìm kiếm & lọc

- [ ] **AC-4 [web]**: Tìm kiếm (inline search bar — Web GMS)

  - Tại: ô tìm kiếm inline (top header, cùng dòng với 3 filter), placeholder **"Tìm theo mã, tên sản phẩm nội bộ"**.
  - Khi: chủ garage nhập từ khóa.
  - Thì: hệ thống lọc theo từ khóa khớp tương đối (LIKE) trên mã / tên sản phẩm nội bộ (map SDL `OpeningBalanceSearchInput.keyword`).
- [ ] **AC-4b [mobile]**: Tìm kiếm (dedicated screen — App Garage)

  - Tại: icon **🔍 search** trên AppBar màn "Tồn đầu kỳ" mobile.
  - Khi: chủ garage tap icon.
  - Thì: hệ thống push route mở **màn Tìm kiếm dedicated** (Figma node `21290:52992`) — AppBar: `← back` + full-width `TextField` placeholder **"Tìm kiếm"**; body 3 state:
    - **Default** (chưa nhập): hint heading **"Tìm kiếm sản phẩm theo từ khoá"** + 2 bullet `Mã sản phẩm` / `Tên sản phẩm`.
    - **Results** (có kết quả): SliverList of card giống canonical `21290:52697` (5 field per card); nếu combine active filters thì server-side áp cả 2 (keyword + filters).
    - **No Results** (`totalElements = 0` sau search): text **"Không có kết quả phù hợp"** (Figma node `21290:53004`).
  - Debounce user input ≥ 300ms trước khi fire query `searchOpeningBalances(input: { keyword, ...activeFilters, page: 0, size: 20 })`.
- [ ] **AC-5 [web]**: Bộ lọc (Web GMS)

  - Tại: 3 bộ lọc inline **"Kho"**, **"Người import"**, **"Ngày Import"**.
  - Khi: chủ garage chọn giá trị.
  - Thì: hệ thống lọc danh sách theo kho / người import / ngày import tương ứng (map SDL `warehouseId` / `createdBy` / `importedFrom`+`importedTo`).
- [ ] **AC-5b [mobile]**: Bộ lọc bottom-sheet (App Garage)

  - Tại: icon **⚙ filter** trên AppBar màn "Tồn đầu kỳ" mobile.
  - Khi: chủ garage tap icon.
  - Thì: hệ thống mở **bottom-sheet title "Bộ lọc"** (verbatim Figma nodes `21290:54167` Default + `21290:54179` Filled) với **2 filter**: (1) **"Ngày Import"** — date-picker range `dd/mm/yyyy - dd/mm/yyyy`, map SDL `OpeningBalanceSearchInput.importedFrom` + `importedTo`; (2) **"Kho"** — dropdown placeholder `"Chọn kho"`, map SDL `OpeningBalanceSearchInput.warehouseId`. Footer buttons: **`[Thiết lập lại]`** (secondary, bên trái) + **`[Áp dụng]`** (primary, bên phải). Apply → close sheet + reset list to page 0 + fetch `searchOpeningBalances` với activeFilters mới. Reset → clear filter values về default (KHÔNG apply, giữ sheet mở). **KHÔNG có filter "Người import"** trên mobile (web-only per AC-5 [web]).
- [ ] **AC-5c [mobile]**: Kho dropdown — paginated + preserve selection (App Garage)

  - Tại: dropdown "Kho" trong bottom-sheet Bộ lọc.
  - Khi: user tap dropdown mở list.
  - Thì: hệ thống call GraphQL `searchWarehouses(input: WarehouseSearchRequest)` per `Architecture/api/agg-garage-graph-graphql` op #305 với **`size=20`** default, load page 0. Khi user scroll dropdown đến cuối trang → fetch next page (`page++`) và append vào list (**load more pattern**), loading indicator cuối list khi fetch. Response: `PagedApiResponseWarehouseResponse.data.content` = danh sách warehouse; `pageInfo.hasNext` = client compute hasNextPage.
  - **Preserve selection logic** (khi user quay lại filter sau khi đã chọn kho ở lần trước):
    - Nếu selected warehouse nằm ở page 0 (trong 20 item đầu) → item render với check-mark "selected" bình thường.
    - Nếu selected warehouse nằm ngoài page 0 (VD ở page N > 0) → khi mở dropdown: (i) load page 0 mặc định; (ii) hiển thị **header/badge "Đang chọn: {warehouseName}"** ở top dropdown để user biết current selection dù item chưa render trong list hiện tại; (iii) khi user load more đến page chứa item đó → item render với check-mark/highlight "selected" state đúng logic (không double-render).
    - Alternative pattern (BA/UX chốt approach cụ thể nếu cần): prefetch page chứa selected item HOẶC "sticky" selected item ở top danh sách.
  - Selection state persist trong bottom-sheet lifecycle: user đóng sheet (chưa Áp dụng) → reopen giữ nguyên selection để user không phải chọn lại.

### Nhóm C — Phân trang & chọn dòng

- [ ] **AC-6 [web]**: Phân trang offset (Web GMS)

  - Tại: cuối bảng.
  - Khi: danh sách nhiều hơn một trang.
  - Thì: hệ thống hiển thị bộ chọn số dòng mỗi trang (mặc định **20**) và điều hướng trang (offset paging).
- [ ] **AC-6b [mobile]**: Phân trang infinite-scroll (App Garage)

  - Tại: cuối SliverList màn "Tồn đầu kỳ" mobile.
  - Khi: user scroll đạt **75% list length** hiện tại (per Architecture/hld/garage-mobile-HLD.md §11b.4 pagination strategy).
  - Thì: hệ thống fetch next page với `page: {current + 1}, size: 20` — client compute `hasNextPage` = `page + 1 < totalPages` từ `PagedOpeningBalanceData`. Loading indicator hiển thị cuối list khi fetch. **KHÔNG có** bộ chọn số dòng / điều hướng trang. Filter/search apply → reset về page 0 + scroll top.
- [ ] **AC-7 [web-only]**: Chọn dòng để xóa (Web GMS)

  - Tại: cột checkbox (gồm checkbox chọn tất cả ở tiêu đề).
  - Khi: chủ garage tích chọn một hoặc nhiều dòng.
  - Thì: hệ thống ghi nhận các dòng được chọn, hiển thị nút **"Xoá các dòng đã chọn"** (theo AC-1 — ẩn ở trạng thái mặc định) để thực hiện xóa hàng loạt (`FEAT-OB-DELETE-LINES`). **Mobile KHÔNG có** — view-only per UX-FLOW §1.
- [ ] **AC-8 [web-only]**: Mở import (Web GMS)

  - Tại: nút **"Import tồn đầu kỳ"**.
  - Khi: chủ garage nhấn.
  - Thì: hệ thống mở wizard import (`FEAT-OB-IMPORT`). **Mobile KHÔNG có** — view-only per UX-FLOW §1.
- [ ] **AC-10 [web-only]**: Sửa dòng (per row) — Web GMS

  - Tại: cột **"Thao tác"**, icon sửa **✏️** trên dòng.
  - Khi: chủ garage nhấn icon sửa.
  - Thì: hệ thống mở form sửa dòng tồn đầu kỳ (`FEAT-OB-EDIT`). **Mobile KHÔNG có** — view-only per UX-FLOW §1.
- [ ] **AC-11 [web-only]**: Xóa dòng (per row) — Web GMS

  - Tại: cột **"Thao tác"**, icon xóa **🗑️** trên dòng.
  - Khi: chủ garage nhấn icon xóa.
  - Thì: hệ thống hiển thị popup xác nhận xóa (cùng luồng `FEAT-OB-DELETE-LINES` — guardrail kỳ đóng + tồn âm áp dụng cho dòng đó). **Mobile KHÔNG có** — view-only per UX-FLOW §1.

- [ ] **AC-9 [cross-platform]**: Phân quyền và phạm vi garage
  - Tại: danh sách tồn đầu kỳ (web + mobile).
  - Khi: chủ garage hoặc kế toán truy cập.
  - Thì: cả hai vai trò xem với quyền ngang nhau; danh sách chỉ hiển thị dòng thuộc garage hiện tại (tenant scope via JWT). Web: 2 role có quyền write (import/edit/delete) ngang nhau. Mobile: 2 role đều view-only (không có write action per UX-FLOW §1).

## 4. API Reference

- Boundary: `gf-inventory` (qua BFF `agg-garage-graph`).
- Lấy danh sách tồn đầu kỳ + filter: Query `[PROPOSED] ListOpeningBalances`.

## 5. Business Rules

- **BR-OB-001**: Cấu trúc dòng tồn đầu kỳ (ngày, kho, mã, ĐVT, SL, giá trị).
- **BR-OB-014**: Tenant isolation + tìm kiếm LIKE + lọc Kho/Người import/Ngày import + dòng Tổng.
- **BR-OB-CMN-001**: Hiển thị Người import / Ngày import.

## 6. Edge Cases

- **EC-1**: Chưa import dòng nào — hiển thị trạng thái rỗng: icon minh hoạ + text **"Không có dữ liệu"** (giữa vùng bảng, không có dòng nào).
- **EC-2**: Dòng Tổng phản ánh theo bộ lọc hiện tại (không phải toàn bộ dữ liệu).

## 7. Out of Scope

- Import tồn đầu kỳ → xem `FEAT-OB-IMPORT`.
- Xóa dòng đã chọn → xem `FEAT-OB-DELETE-LINES`.
