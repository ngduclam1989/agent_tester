## 2. Scope

### In Scope

- Mutation `updateServiceOrderV3` (→ gf-sales `PUT /api/v3/service-orders/{id}`): lưu 8 scalar adjustment fields + `depreciationByLine` (AC-13, BR-INS-SO-ADJ-002/003/004)
- Query `getServiceOrderByCode` (additive `insuranceAdjustment`: breakdownByPayer / adjustments / settlementBalance) — đọc kết quả tính server-side (AC-9..11)
- REST snapshot `GET /protected/v1/service-orders/{tenantId}/{id}/for-settlement` — 8 breakdown + 8 adjustment fields, idempotent (ADR-014, CB-INS-002)
- Mutation `createInsuranceSettlement(id, input)` — pull `for-settlement` → persist cặp KH+BH atomic → settle callback; rollback toàn bộ khi callback fail
- Query `getSettlementByCode` INSURANCE → block `insurance` + `debtPanel`; CUSTOMER → KHÔNG có block `insurance`
- Mutation `cancelSettlement` (reuse baseline) cascade huỷ cặp KH+BH; block khi đã có payment
- Field-level validation: empty, 0, âm, % > 100, biên 100, mode sai (`INVALID_ALLOCATION_MODE`), kiểu dữ liệu sai, payable null/âm/chuỗi
- Công thức tính server-side (BR-INS-SO-ADJ-005) + single-payer edge (CALC-INS-006) + snapshot khớp allocation SO
- Discard allocation khi toggle BH=Có → BH=Không (8 adjustment columns + depreciationByLine clear; for-settlement không leak; no stale resurrection)
- API-Security: authz (no token / role / IDOR / token expired / signature tampering), tenant isolation, OriginTenantId integrity, injection, response schema, leak sensitive
- Performance: SO Edit save với allocation p99 < 800ms (PKG §4.3); GET chi tiết phiếu QT BH p99 < 600ms (PKG SLA); createInsuranceSettlement success rate ≥ 99.5%
- Regression (R2): `updateServiceOrderV3` / `getSettlementByCode` / `for-settlement` / `cancelSettlement` dùng chung SO thường / phiếu KH baseline vẫn đúng

### Out of Scope

- UI section "Phân bổ quyết toán bảo hiểm" (xem file `TC-W01-UI.md`)
- Luồng end-to-end + tạo phiếu QT BH cross-boundary từ góc nhìn user (xem file `TC-W01-E2E.md`)
- Tạo hồ sơ BH (FEAT-INS-DOSSIER-CREATE — W02), xem hồ sơ đã xuất (FEAT-INS-DOSSIER-VIEW — W02)
- Ghi nhận / đối soát thanh toán BH chi tiết (baseline production, FEAT-STL-DETAIL)
- Dashboard công nợ BH (FEAT-INS-DASH-DEBT — deferred)
- Khu vực thông tin BH baseline (toggle, dropdown CTBH, upload hồ sơ bảo lãnh — đã production)
- Cột Nguồn TT per line item (baseline production)

## 2.5 API Tác Động

> Gộp từ FEAT §4 API Reference + PKG §2.2 Technical Scope của 2 features W01. Mapping GraphQL op (agg-garage-graph) ↔ REST downstream (gf-sales / gf-accounting). Cột "Trạng thái" = Thêm mới / Update (additive trên op/endpoint hiện hữu) / Update (REUSE) khi endpoint baseline dùng chung. Đã dedup các op xuất hiện ở cả 2 feature.

| Service | Endpoint/Operation | Method | Trạng thái (Thêm mới/Update) | Mô tả thay đổi |
|---|---|---|---|---|
| agg-garage-graph | `updateServiceOrderV3` (mutation) | GraphQL mutation | Update (additive input) | Thêm input 8 scalar adjustment fields (discountMaterial/discountLabor mode+value, depreciationDefault.percent, claimReduction mode+value, insuranceDeductible.amount) + `depreciationByLine[]`. Dùng chung cho SO thường + SO BH. |
| gf-sales | `PUT /api/v3/service-orders/{id}` | PUT | Update (additive) | Persist 8 scalar adjustment columns trên `service_order` + `depreciation_percent` trên `service_order_part` (ddl-auto). Calc inline server-side. |
| agg-garage-graph | `getServiceOrderByCode` / `getServiceOrder` (query) | GraphQL query | Update (additive block) | Response thêm block `insuranceAdjustment`: `breakdownByPayer`, `adjustments`, `settlementBalance` (computed server-side). |
| gf-sales | `GET /api/v3/service-orders/{code}` (detail) | GET | Update (additive) | Trả thêm allocation + breakdown + settlementBalance đã tính. |
| gf-sales | `GET /protected/v1/service-orders/{tenantId}/{id}/for-settlement` | GET | Update (additive) | Snapshot provider: 8 breakdown + 8 adjustment scalar fields + `insurancePayableAmount` cho gf-accounting pull (CB-INS-002, ADR-014). Idempotent. |
| agg-garage-graph | `createInsuranceSettlement(id, input)` (mutation) | GraphQL Mutation | Thêm mới | Mutation mới (agg #44) → gf-accounting `POST /api/v1/service-orders/{id}/settlements` với pull snapshot (KHÔNG push từ SO). Tạo cặp KH+BH atomic + settle callback gf-sales. |
| agg-garage-graph | `getSettlement` / `getSettlementByCode` (query) | GraphQL Query | Update | Additive block `insurance` + `debtPanel` khi `payerType=INSURANCE`; → gf-accounting `GET /api/v1/settlements/{code}`. Phiếu CUSTOMER KHÔNG có block `insurance`. |
| gf-accounting | `POST /api/v1/service-orders/{id}/settlements` | POST | Update (REUSE) | Request additive 8 adjustment + 8 breakdown + `insurancePayableAmount`; persist cặp CUSTOMER+INSURANCE atomic qua `related_settlement_code`. Rollback toàn bộ khi settle callback fail (ADR-014). |
| gf-accounting | `GET /api/v1/settlements/{code}` | GET | Update (REUSE) | Response additive block `insurance` + `debtPanel` (4 tab data); KHÔNG endpoint mới. |
| gf-accounting | `CancelSettlement` (cancel settlement) | Mutation/POST | Update (REUSE) | Cascade huỷ cặp KH+BH; block khi đã có payment (AC-11, BR-INS-STL-DET-003). |
| gf-sales | `settle` / `reopen-from-settled` callback | POST | Update (REUSE) | Tái dùng endpoint baseline (CB-INS-003); cascade reopen khi huỷ phiếu QT BH. |
