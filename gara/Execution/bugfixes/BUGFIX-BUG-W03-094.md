# BUGFIX — BUG-W03-094

> Live Figma re-audit follow-up on the GRP-list card (`FEAT-CAT-GRP-LIST`): the "Thuộc nhóm" InfoField icon substitute (`icClipboardTick`, chosen in `BUG-W03-069`, surveyed-and-kept in `BUG-W03-076`) was never a floppy-disk shape, and both "Thuộc nhóm" + "Mô tả" InfoField icons had a `color:` tint applied that overrode each SVG's real baked Figma color. User explicitly authorized importing a new icon asset into the app's asset library.
> Severity: **P2** · Boundary: `garage-mobile` · Status: **FIX_DONE** · Date: 2026-07-02

## 1. Summary

`group_list_card.dart` (shared by `material_group_list_page.dart` and `material_group_search_page.dart`) renders two InfoField rows in the group card body: "Thuộc nhóm" (parent group) and "Mô tả" (description, when present). Each row is prefixed with a 16x16 leading icon. Live Figma node `21235:29063` (file `5YU4H3iY726P8KNxI9oCYF`) confirms:

- "Thuộc nhóm" icon = `vuesax/linear/floppy-disk`, baked `stroke/fill: #111928`.
- "Mô tả" icon = `vuesax/linear/note`, baked `stroke: #334155`.

Prior to this fix, "Thuộc nhóm" rendered `Assets.icons.icClipboardTick` (a clipboard+checkmark glyph — wrong shape entirely, carried over as a stand-in from `BUG-W03-069` because no floppy-disk asset existed in the catalog at the time; `BUG-W03-076` re-surveyed the catalog and confirmed no closer match existed, so it was left unchanged). "Mô tả" rendered `Assets.icons.icNoteSvg` (the correct semantic icon, shape-wise). Both calls additionally passed `color: AppColors.textTertiary` (`#888c94`), which does not match either real Figma color.

## 2. Root cause

- **Shape ("Thuộc nhóm")**: no `floppy-disk`/`save`-shaped SVG asset existed anywhere in `assets/icons/` (confirmed independently in `BUG-W03-069` and `BUG-W03-076` by name-grep + full manual catalog survey) — `icClipboardTick` was picked only by elimination, never a genuine shape match.
- **Color (both icons)**: `AppImage` (`lib/ui/widgets/images/app_image.dart`) renders SVGs via `SvgPicture.asset(..., colorFilter: widget.color != null ? ColorFilter.mode(widget.color!, BlendMode.srcIn) : null)`. Passing any non-null `color:` unconditionally overrides the SVG's own embedded stroke/fill with a flat tint. `BUG-W03-069`'s fix passed `color: AppColors.textTertiary` for both icons without checking the real Figma color values — `#888c94` does not match either `#111928` (floppy-disk) or `#334155` (note).

## 3. Fix

- **New assets**: saved the real Figma SVG exports verbatim (only cosmetic cleanup: `var(--stroke-0, #hex)` CSS-variable syntax → plain hex attributes, matching this app's existing convention, e.g. `ic_note.svg` already uses raw `stroke="#273243"`, not CSS vars) as:
  - `assets/icons/ic_floppy_disk.svg` — baked `#111928` (exact match `NeutralColor.s950`, `app_colors.dart:121`).
  - `assets/icons/ic_note_grp_card.svg` — baked `#334155` (no exact `AppColors`/`NeutralColor` token match; kept as the SVG's own fixed color per this app's established precedent, e.g. `ic_note.svg`'s `#273243`). Named distinctly from `ic_note.svg`/`note.svg` to avoid altering those files' other consumers, which use a different embedded color.
  - `pubspec.yaml` unchanged — `pubspec.yaml:151` already declares the whole `assets/icons/` directory.
- **`group_list_card.dart`**:
  - "Thuộc nhóm" `AppImage` call: `Assets.icons.icClipboardTick.path` → raw string `'assets/icons/ic_floppy_disk.svg'`; removed `color: AppColors.textTertiary`.
  - "Mô tả" `AppImage` call: `Assets.icons.icNoteSvg` → raw string `'assets/icons/ic_note_grp_card.svg'`; removed `color: AppColors.textTertiary`.
  - Both calls use a raw path string instead of the generated `Assets.icons.*` typed accessor because `lib/generated/assets.gen.dart` is gitignored (`.gitignore:147`, `/lib/generated/`) and only regenerated by `flutter gen-asset` / `build_runner` codegen, which this FIX cycle does not run — documented inline at both call sites.
  - Removed the now-unused `import 'package:cardoctor_garage_v3/generated/assets.gen.dart';`.
  - Net effect: `AppImage`'s `colorFilter` branch is skipped (no `color` param → `null`), so each SVG's own baked color renders natively — consistent with how `ic_note.svg`/`note.svg` already bake their own presentation colors elsewhere in this app.
- **`group_list_card_icons_test.dart`** (existing regression test from `BUG-W03-069`): 3 of its 4 test cases previously asserted the *old, buggy* icon path + `color: AppColors.textTertiary` as the expected/passing behavior. Since that behavior is exactly what this bug fixes, those assertions were updated to assert the new asset paths and `icon.color == null`. The 4th case (8px InfoRows gap, unrelated to icon shape/color) is untouched. This edit is in-scope per this FIX cycle's explicit instruction to touch `group_list_card.dart` + its test file(s) — it is not an unrelated test-logic change, it is updating a test that encoded the reported bug as "correct."
