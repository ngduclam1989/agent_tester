## BUG-W02-087 — Màn Tạo phiếu QT: box `CostSummarySettlementWidget` thừa khi SO có BH

### Root cause (HEAD)
`settlement_create_page.dart`: box legacy vẫn render trong cả 2 section khi SO có BH, trùng với panel canonical `InsuranceSettlementDetailView` (dòng 87-92):
- `_buildCustomerSection()` dòng **125**: `CostSummarySettlementWidget(cubit.customerCostSummary)`
- `_buildInsuranceSection()` dòng **173**: `CostSummarySettlementWidget(cubit.insuranceCostSummary)`

### Fix — ẩn box khi `soHasInsurance` (panel canonical thay thế)
```diff
@@ _buildCustomerSection (dòng 125)
-        CostSummarySettlementWidget(cubit.customerCostSummary),
+        if (!cubit.soHasInsurance) CostSummarySettlementWidget(cubit.customerCostSummary),
@@ _buildInsuranceSection (dòng 173)
-        CostSummarySettlementWidget(cubit.insuranceCostSummary),
+        if (!cubit.soHasInsurance) CostSummarySettlementWidget(cubit.insuranceCostSummary),
```
SO KHÔNG BH → `soHasInsurance=false` → box giữ nguyên (panel canonical không render — không hồi quy).

## BUG-W02-091 — Panel hiển thị nhầm bên thanh toán (mặc định KH thay vì BH)

Logic khoá bên trong panel (`insurance_settlement_detail_view.dart:102-114`):
`lockToCustomerSide == null` → có tab, mặc định KH · `== true` → khoá KH (ẩn CK rows) · `== false` → khoá BH.
Reference ĐÚNG = màn Chi tiết `insurance_settlement_detail_screen.dart:165`:
`lockToCustomerSide: detailData?.settlementType == SettlementType.customer`.

### (a) Màn Sửa — `lockToCustomerSide: true` HARDCODED (REAL, fixable)
`settlement_edit_page.dart:94` hardcode `true` → mọi phiếu (kể cả phiếu BH) đều khoá KH + ẩn CK rows → SAI.
Edit cubit có `_data?.isCustomerType` (đã dùng ở `settlement_edit_cubit.dart:107`).

```diff
@@ settlement_edit_cubit.dart (thêm getter, cạnh soHasInsurance)
+  /// Phiếu KH (CUSTOMER) → khoá bên KH; phiếu BH (INSURANCE) → khoá bên BH.
+  bool get isCustomerType => _data?.isCustomerType ?? false;
@@ settlement_edit_page.dart:91-95
                 if (cubit.soHasInsurance)
                   InsuranceSettlementDetailView(
                     snapshot: cubit.insuranceSnapshot,
-                    lockToCustomerSide: true,
+                    lockToCustomerSide: cubit.isCustomerType,
                   ),
```

### (b) Màn Tạo — ⚠️ CẦN XÁC NHẬN BA (không có settlementType)
`settlement_create_page.dart:92` truyền null → có tab, mặc định KH. NHƯNG luồng Tạo **không có
settlementType**: vào từ SO detail (`SettlementCreateRoute(serviceOrderDetailV3: detail)`), cubit
dựng cả 2 section KH+BH từ payer-split của 1 SO (combined create) — KHÔNG có cờ phiếu-KH vs phiếu-BH.

→ ✅ **BA QUYẾT (2026-06-25): GIỮ TAB** — luồng Tạo là combined create, để kế toán xem cả 2 bên KH/BH
trước khi tạo. ⇒ **091(b) màn Tạo = by-design, KHÔNG đổi code** (`settlement_create_page.dart:92` giữ
nguyên `lockToCustomerSide: null` = có tab). Chỉ áp **091(a) màn Sửa**.
